# Twitch Live Watch — фоновая проверка через GitHub Actions + ntfy

Этот комплект проверяет каналы на сервере GitHub Actions примерно каждые 5 минут и отправляет уведомление в ntfy при переходе **оффлайн → онлайн**. Браузер и телефон могут быть закрыты.

## Что уже настроено

- ntfy topic: `twitch_lw_kostya_73921_x8p4m2`
- начальный канал: `skillightv`
- проверка: каждые 5 минут
- первый запуск только запоминает текущие статусы; уведомление придёт при следующем переходе канала из офлайна в эфир.

## Установка с телефона

1. Открой https://github.com и войди в аккаунт. Создай новый репозиторий, например `twitch-live-watch-background`. Для простоты можно выбрать **Public**; не загружай туда пароли или приватные данные. В этом комплекте секрет ntfy будет сохранён отдельно в GitHub Secrets.
2. Распакуй этот ZIP на телефоне или компьютере.
3. Загрузи в корень репозитория файлы `monitor.py`, `channels.txt`, `README_RU.md` и папку `.github/workflows/` вместе с `twitch-monitor.yml`. В GitHub при создании файла можно указать путь целиком: `.github/workflows/twitch-monitor.yml`.
4. Открой репозиторий → **Settings** → **Secrets and variables** → **Actions** → **New repository secret**.
5. Создай secret:
   - Name: `NTFY_TOPIC`
   - Secret: `twitch_lw_kostya_73921_x8p4m2`
6. (Необязательно) В **Variables** → **New repository variable** создай `NTFY_SERVER` со значением `https://ntfy.sh`. Если переменная не задана, скрипт использует этот адрес автоматически.
7. Открой вкладку **Actions**. Если GitHub предложит разрешить workflows, нажми **I understand my workflows, go ahead and enable them**.
8. Открой workflow **Twitch Live Watch background monitor** → **Run workflow** → **Run workflow** для первого тестового запуска.
9. Открой **Actions** и проверь, что запуск завершился зелёным статусом. Убедись, что приложение ntfy подписано на тему `twitch_lw_kostya_73921_x8p4m2` и Android разрешил уведомления.

## Как добавить или удалить каналы

Открой `channels.txt` и оставь по одному Twitch-логину на строку. Например:

```text
skillightv
shroud
ninja
```

Сохрани изменение в default branch. На следующем запуске GitHub Actions начнёт проверять новый список.

## Как это работает и ограничения

- GitHub Actions запускает задачу по расписанию; минимальный интервал расписания — 5 минут. Фактический запуск может задерживаться из-за нагрузки GitHub.
- DecAPI кэширует `viewercount` до 5 минут, поэтому уведомление может прийти с дополнительной задержкой. Это публичный сторонний сервис, его доступность не гарантируется.
- Первый запуск создаёт исходное состояние без уведомлений. Уведомление отправляется только при подтверждённом изменении `offline → online`, чтобы не присылать ложные повторные сообщения.
- Статус хранится в `state.json`, который workflow автоматически обновляет в репозитории. Workflow требует разрешение `contents: write`.
- GitHub может приостанавливать запланированные workflows в неактивных репозиториях; расписание не является гарантией доставки в точную минуту.
- Если все каналы недоступны в одном запуске, job будет отмечен как неуспешный. Ошибки отдельных каналов не меняют сохранённый статус.

## Если уведомления не приходят

1. Проверь, что ntfy подписан именно на `twitch_lw_kostya_73921_x8p4m2`.
2. Проверь разрешение уведомлений ntfy в Android и отключи для него ограничения батареи, если Android их применяет.
3. В GitHub открой **Actions** и проверь журнал последнего запуска.
4. Проверь наличие секрета `NTFY_TOPIC` без лишних пробелов.
